# Governance

Mainspring is currently maintainer-led.

## Current Model

- architectural direction stays centralized while the runtime spine is still moving quickly
- bug fixes, docs improvements, and narrowly scoped tool/runtime contributions are welcome
- large directional shifts should be discussed before implementation

## Decision Priorities

1. Keep security and product claims honest.
2. Preserve the runtime spine and mailbox/event-journal architecture.
3. Prefer code and tests over aspirational architecture.
4. Favor local-first operator workflows over vague platform promises.

## Future Direction

As the project stabilizes, governance can expand into clearer RFC, release, and maintainer policies.
